Ensō is open source and unminified: https://github.com/davidwickerhf/enso (extension/ is this add-on; helper/ is the native app). Nothing is bundled, minified or generated; the submitted files are the files in extension/ at the tag for this version.

Why the permissions:
- nativeMessaging: the add-on is the browser half of a local helper app ("enso", a Node.js program the user installs on macOS with `curl -fsSL https://enso.wicker.life/install.sh | sh`). The helper runs the AI (Claude, through Claude Code or the user's Anthropic API key) and the user's tools; the add-on shows the chat, new tab and settings, and carries out page actions for it.
- <all_urls>, tabs, webNavigation, webRequest, cookies: the user asks Claude about, or to act on, the page they're on, in whichever site that is. The content script (pageagent.js) is injected on demand to read the page and click/type when asked. webRequest/webNavigation keep a per-tab network and console log in memory for the developer tools (never request or response bodies). cookies is used for signed-in requests on sites the user explicitly allowed; cookie values are never sent to the model.
- history, bookmarks, search: new-tab suggestions and the history search tool. tabGroups, contextualIdentities: Zen spaces and tab groups. menus, clipboardWrite, storage: context menu entries, copying, settings.

Dynamic code: the extension contains no remote or bundled code that is downloaded or executed. One developer tool, page_eval (Settings → Developer, can be switched off), evaluates a JavaScript expression in the page's own world through window.wrappedJSObject.eval (pageagent.js, evaluate()), so a user debugging their own web app can ask Claude to read the page's state. It never runs in the extension's privileged context, refuses on private sites, asks the user for approval in Ensō unless they asked for it, refuses document.cookie, and every call is logged in the activity log. This is the "eval" the linter reports.

Safety: banking, payment, password-manager, health, tax and government sites are never read or acted on (list: helper/config.json sensitiveHosts, copied in background.js). Irreversible actions always ask the user. There is no analytics or telemetry. The add-on's only direct network request is search suggestions from the user's default engine (Google or DuckDuckGo, credentials omitted) while they type in the new tab's search box; everything else goes through the native helper.

Testing without the helper: install the add-on and open a new tab or the sidebar (Ctrl+E). Without the helper, Ensō shows a guided setup: why the helper is needed, the install command with a Copy button, and it moves on by itself when the helper connects. To see the full UI without the helper: serve the extension folder over http (`cd extension && python3 -m http.server 8000`) and open http://127.0.0.1:8000/newtab.html or /sidebar.html. Outside the extension, ui/transport.js uses an in-page mock helper (ui/mock.js) with a fictional user; docs/development.md in the repository describes it.
